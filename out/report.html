If the English and Swedish help pages disagree, a chatbot that reads both could give two different answers.

Everything below uses help pages I wrote myself for a made-up airline. No Finnair content or data.

What the tool does

  • Compares each translated help page with the English one.
  • Points out where they disagree: a different number, a missing section, a missing or dead link, or a page that wasn't updated after the English one changed.
  • Shows where the pages give different numbers for the same customer question.

What I found, on a test set I wrote myself

I wrote the same 5 help pages in English, Finnish, Swedish and German, and put 11 mistakes in them on purpose. I wrote both the mistakes and the tool, so this only shows the tool works as designed. It says nothing about real help pages. The tool caught 10 of 11. The one it missed I planted so number checks couldn't catch it. It flagged 11 things, and 10 of those were real. The simple check, “is the translation older than the English page?”, caught 2 of 11.

Limits

  • It misses changes in meaning. My Swedish refunds page says non-refundable tickets can be refunded, the opposite of the English. No number changed, so the tool didn't notice.
  • It can flag correct pages. My Finnish page says “three weeks” in words where the English says “21 days”. That's correct, but the tool only looks for numbers, so it reported a missing deadline. I wrote that page that way on purpose, to see how the tool handles numbers written as words.

An open question

If you run a help centre in more than one language: do the versions ever disagree like this? Or does your translation setup already stop it?
